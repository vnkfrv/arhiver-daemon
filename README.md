# Архивация видеоконференций Talk

Демон, работающий нон-стоп: берёт из **Контур.Толк** записи конференций,
«архивирует» их (расшифровка + короткая выжимка + запись в БД), уведомляет участников
в **Tag (Mattermost)** и по расписанию удаляет видео из Толка, а тексты хранит 5 лет.

Два процесса во времени разнесены (по ТЗ):
- **Архивация — рано.** Раз в сутки (в `RUN_AT`, по умолч. 00:01) транскрибируем записи
  прошлого дня → текст доступен на следующий день (виден в модалке «Найти видеозапись»).
- **Утилизация видео — поздно.** Когда видео старше года — уведомляем участников и
  через неделю реально удаляем из Толка.
- **Очистка текстов — ещё позже.** Через 5 лет после удаления видео файлы удаляются.

Конвейер одной записи (машина состояний, идемпотентная):

```
transcribe → improve (LLM) → summarize (LLM) → save_to_db      (рано)
   → messages → delete            (когда видео старше года)
   → cleanup_text                 (через 5 лет после удаления видео)
```

Админ (задаётся в `ADMIN_USERNAME`, добавляет других командой `newadmin_{nickname}`)
в ЛС бота может `remember_{ID}` — сохранить видео в Толке навсегда (защита от удаления),
или `delete_{ID}` — удалить видео вручную.

Статус записи меняется на каждом этапе: `до преобразования → выполнена транскрибация →
выполнено ЛЛМ-преобразование → выполнена короткая выжимка → выполнено сохранение в
систему → разосланы сообщения в Tag → Видеозапись удалена`.

## Режимы (MODE)

Логика подхвата одинакова (все записи из API, от старых к новым); режимы различаются
только удалением и темпом:

| | test | prod |
|---|---|---|
| Что обрабатываем | всё из API, от старых к новым | всё из API, от старых к новым |
| Возрастной порог | да (видео старше года → рассылка/удаление) | да |
| Удаление видео | **имитация** (только лог, видео не трогаем), задержка `test=180с` | реальное, задержка `prod=604800с` (неделя) |
| Темп | частый цикл `TEST_CYCLE_SEC` | суточно в `RUN_AT` или в окне `TIME_START–TIME_END` |

## Производительность и рабочие окна

- **Параллельная обработка записей — главный рычаг скорости.** `RECORD_WORKERS`
  НЕЗАВИСИМЫХ воркеров, у каждого своя запись (куски внутри — последовательно). Это же
  число = одновременных запросов к шлюзу. Больше воркеров → быстрее разбор. У каждого
  воркера свой `TalkClient`; БД и лимитер — общие. Воркеры не пересекаются (множество
  `inflight`), новый берётся сразу как освободился (не ждёт соседей).
- **Лимит частоты шлюза.** Запросы к MagnitGPT (ASR + LLM) не быстрее `ASR_LLM_RPM`
  (скользящее окно 60с), общий на ASR+LLM.
- **Логи.** Каждая строка помечена `[воркер|запись]`; отдельный файл на воркер
  `logs/rec_N.log` (чистая последовательность его записей) + общий `logs/daemon.log`.
- **Раздельные рабочие окна** (ЧЧ:ММ, можно через полночь):
  - `TIME_START_ASR`/`TIME_END_ASR` — окно **транскрибации** (обычно шире, напр. 14:00–05:00):
    готовит расшифровки, статус `выполнена транскрибация`.
  - `TIME_START_LLM`/`TIME_END_LLM` — окно **LLM-обработки** (уже, напр. 23:00–05:00):
    improve/summarize + пост-стадии (БД, рассылка, удаление, очистка) над готовым.
  - Фоллбэк — общие `TIME_START`/`TIME_END` (одно окно на обе фазы). Все пустые → без окон
    (`RUN_AT` в prod / короткий цикл в test).
- **Окно проверяется перед стартом записи**; начатую транскрибацию демон доводит до
  конца (не обрывает по `TIME_END`). Не успел за ночь — продолжит следующей (состояние в БД).

## Установка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить ключи
```

Нужен системный **ffmpeg/ffprobe** (декод аудио для ASR).

## Запуск

Два процесса (общий `.env` и БД):

```bash
python main.py            # ДЕМОН архивации (бесконечно)
python main.py --once     # один тик и выход
python main.py --record <recordingKey>   # обработать одну запись и выйти

python bot.py             # ИНТЕРАКТИВНЫЙ бот Tag (кнопки/модалка/выдача файлов)
```

- Демон архивирует записи и (если `SEND_TO_TAG=1`) рассылает участникам ЛС с кнопками.
- Бот `bot.py` обрабатывает нажатия кнопок и модалку, отдаёт файлы **в ветку**.
- Кнопки уведомления ведут на `BOT_PUBLIC_URL/action` — этот адрес должен быть
  доступен серверу Tag; порт = `BUTTON_PORT`.

**Безопасность рассылки:** по умолчанию `SEND_TO_TAG=0` — демон только пишет в лог,
кому бы отправил (никто ничего не получает). Поставь `SEND_TO_TAG=1`, только когда
бот поднят и `TEST_RECORD_KEYS` указывают на безопасные записи.

## Логика бота (Tag)

- **ЛС + любое сообщение боту** → help-сообщение + кнопка «Найти видеозапись».
  Бот отвечает ТОЛЬКО в ЛС; сообщения из каналов игнорирует.
- **Кнопки уведомления** «Видеозапись» / «Вся расшифровка» / «Короткая выжимка» →
  соответствующий файл в ветку. Видео скачивается из Толка по запросу; если оно уже
  удалено — «Видеозапись была уже удалена😔» (1 раз на ветку).
- **«Найти видеозапись»** → модалка «Видеозаписи»: select записи пользователя (из БД,
  `{название} - ДД.ММ.ГГГГ`) + select действия. После подтверждения — «Скоро пришлю
  файл….» и сам файл в ту же ветку.

### Админ-команды (в ЛС, текстом)

Первый админ задаётся в `ADMIN_USERNAME` (заносится в таблицу `admins` при старте бота).

- `newadmin_{nickname}` — назначить администратором (только админ).
- `remember_{ID}` — пометить видео «хранить в Толке навсегда» (снимает запись с
  авто-удаления). Пока видео доступно (в течение года) — любой админ может защитить.
- `delete_{ID}` — удалить видео вручную сейчас; работает для **любого** видео, включая
  защищённое `remember` (защита при этом снимается).

## Раскладка на диске

Папки записей ШАРДИРОВАНЫ по дате (`ГГГГ/ММ`), чтобы в одной директории не копились
сотни тысяч подпапок при потоке в сотни записей/день:

```
Transcripts/<ГГГГ>/<ММ>/<ID>/
    <ID>_full.md          # шапка (Название/Дата/Длительность/Участники) + расшифровка
    <ID>_short.md         # короткая выжимка (LLM)
data/recordings.db        # SQLite: витрина (поля ТЗ) + флаги стадий + планировщик
logs/daemon.log           # логи всех этапов
```

**Планирование — в БД, без обхода файлов.** Всё состояние пайплайна (флаги стадий,
тайминги, `done`/`next_due_at`, путь к папке) хранится в строке `recordings`. Демон
берёт из БД только записи, которым пора работать (`due_records` по индексу
`(done, next_due_at)`), от старых к новым. Ждущие записи (постаревшие до удаления, срок
удаления видео, 5-летняя очистка) не трогаются, пока не наступит их срок. Поиск записей
пользователя — по индексу `participant(email)`, без скана. В папке только два итоговых
`.md` — промежуточных файлов нет.

`<ID>_full.md` начинается с шапки, затем идёт расшифровка:

```
Название: <название конференции>
Дата создания: <ДД.ММ.ГГГГ>
Длительность: <X> мин
Участники конференции: <имена через запятую>

Иван Иванов [00:00:05-00:01:03]: …
```

> При обновлении со старой версии удали прежний `data/recordings.db` — схема БД изменилась.

## Модули

- `talk_api.py` — клиент Толка: список записей, детали, `login→email` (`/api/users/{login}`),
  скачивание аудио (`/api/recordings/{key}/audio`) и видео (`/api/recordings/{key}/file`),
  удаление. Плюс общие утилиты (`load_env`, `hhmmss`).
- `asr.py` — MagnitGPT_ASR: канал → mono WAV 16к → пословная расшифровка (ретраи).
- `transcribe.py` — аудио → диалог по времени (реплики + слова).
- `llm.py` — чат-LLM MagnitGPT (OpenAI-совм. `/chat/completions`).
- `enrich.py` — `enrich_blocks` (полная расшифровка) и `summarize_text` (выжимка).
- `store.py` — файловое хранилище выходных файлов (шардинг по дате).
- `db.py` — SQLite: единый источник правды (витрина + флаги стадий + планировщик).
- `statuses.py` — человекочитаемые статусы стадий.
- `notify.py` — рассылка уведомлений участникам (через `mm_client`, либо лог-заглушка).
- `mm_client.py` — клиент Tag (Mattermost REST v4): ЛС, посты/файлы в ветку, модалки.
- `bot.py` — интерактивный бот (websockets + Flask): кнопки, выдача файлов, модалка.
- `pipeline.py` — стадии обработки одной записи (поверх строки БД) + планирование.
- `config.py` — конфиг из `.env` (режимы, БД, Tag).
- `main.py` — демон: подхват записей + обработка «кому пора» из БД + сон.

## Статус

- **Этап A (готово):** ядро архивации — ASR, LLM-правка, короткая выжимка, БД,
  раскладка `Transcripts/<ID>`, статусы, режимы test/prod, планировщик удаления.
- **Этап B (готово):** интерактивный Tag-бот — рассылка с кнопками «Видеозапись» /
  «Вся расшифровка» / «Короткая выжимка», выдача файлов в ветку, модалка «Найти
  видеозапись», ответ «Видеозапись была уже удалена», общение только в ЛС.
- **Следующий этап:** сохранение фрагментов видео с демонстрацией экрана.

> Примечание: шлюз ASR/LLM (`llmlite.ai.corp.tander.ru`) — во внутренней сети;
> запускать демон нужно с хоста, откуда он резолвится.
